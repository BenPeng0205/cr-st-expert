# 黄金样本准入策略

## 核心原则

黄金样本不是“看起来合理的示例代码”，而是当前技能愿意长期承担回归责任的交付资产。

当没有十足把握、没有经过当前门禁验证、没有被清楚标注适用边界时，任何 ST 代码都不得进入 `examples/` 或 `examples/example_manifest.json`。这类代码只能进入 `examples/candidates/`，作为候选样本继续打磨。

## 样本分层

| 层级 | 路径 | 含义 | 能否作为可复制模板 |
|---|---|---|---|
| 黄金样本 | `examples/` | 已纳入 manifest 并通过门禁的稳定样本 | 可以在相同边界内参考复用 |
| 候选样本 | `examples/candidates/` | 仍需审查、编译或现场验证的草案 | 不能宣称可直接复制 |
| 参考片段 | `references/` | 说明模式、陷阱或写法的片段 | 只能按上下文改造 |
| 模板 | `templates/` | 对象结构模板 | 必须填充业务语义后使用 |

## 黄金样本准入条件

进入 `examples/example_manifest.json` 前必须同时满足：

1. 文件边界明确，且每个 DUT 独占文件。
2. 文件头、库依赖、完整功能注释块满足技能规则。
3. 变量注释包含工程语义，物理单位使用 `[unit]`。
4. 不含 `(* *)`、Tab、裸单位、空实参、重复枚举值。
5. FB / FC / PRG 的完整功能注释块位于 `// === IMPLEMENTATION ===` 后。
6. `使用说明` 至少包含两条编号内容：`1.` 说明调用条件或文件拆分边界，`2.` 说明关键使用约束。
7. 每个包含可执行代码的 `// === IMPLEMENTATION ===` 段必须包含工程师级 `//` 注释；复杂实现段必须按逻辑块补充多条注释。
8. 当前仓库的 `python evals/run_delivery_gate.py` 通过。
9. 内置 public_asset_guard.py 通过，确认公开文件可 UTF-8 解码且无本机信息；不要求外部工具。
10. 如果依赖平台库或厂商库，必须在文件头和 manifest 中写明库依赖。
11. 如果尚未经过真实 CODESYS / CODESYS 编译，应在 manifest 中保守标注验证层级，禁止宣传为“已现场验证”。

## 候选样本规则

候选样本必须显式写明：

- `验证状态`
- `未决问题`
- `不可直接复制说明`
- `进入黄金样本所需证据`

候选样本可以帮助技能自迭代，但不得被 delivery gate 当作黄金样本。

## 自迭代原则

技能每次生成或修复 ST 代码后，应把暴露出的稳定经验沉淀到：

1. `docs/evolution-log.md`
2. 对应 `references/rules/*.md`
3. 对应 validator 或 eval
4. 必要时再进入候选样本

只有当规则、样本、校验三者闭环后，才允许把候选样本晋升为黄金样本。
