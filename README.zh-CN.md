# cr-st-expert

[English](README.md) | **简体中文**

### 一本给 AI 看的 CODESYS ST 工程编程规范手册。

`cr-st-expert` 是独立的 CODESYS ST 编程规范技能。它把工程约定、部分平台规则、模板和示例交给 AI，让写代码、改代码和审查代码有同一套依据。

目标很具体：名字更容易理解，接口和注释更清楚，状态与扫描周期的检查更明确，修改更容易比较和维护。实际需求由工程师提供，生成结果仍需复核。

**它不是编译器，帮助减少错误，但不保证代码零报错，也不保证设备行为正确。**

## 八类规则，具体帮助什么

| 类别 | 主要约定 | 工程收益 |
| --- | --- | --- |
| 命名与接口 | 对象采用 PascalCase；变量采用匈牙利前缀；明确默认值、单位和接口语义 | 少猜类型和用途，调用更清楚 |
| 注释与格式 | 四空格缩进；声明和命名参数对齐；注释解释工况、原因和边界 | 更容易阅读、比较和交接 |
| 对象与文件组织 | 单一职责；区分 FB、FUNCTION、PROGRAM；明确对象与文件关系 | 更容易定位修改点和复用组件 |
| 类型与计算 | 显式转换、范围检查、浮点容差和除零保护 | 提前发现计算中的隐含假设 |
| 扫描周期 | 状态型实例稳定调用；检查实例生命周期、定时器和触发器用法 | 核对输入变化时状态怎样更新 |
| 状态与诊断 | 严格枚举和限定访问；CASE 异常出口；错误上下文与复位边界 | 说明哪个状态出了什么问题 |
| 边界与共享数据 | 数组、字符串、指针边界；共享数据读写职责和同步检查 | 识别不安全访问和任务之间的冲突 |
| 依赖与审查 | 写实际库标识；未知版本待确认；报告范围、位置、原因和建议 | 不把猜测变成工程事实 |

这些规则包含工程约定、标准用法及部分 CODESYS 扩展，不是官方 IEC 认证，也不是所有厂商强制使用的统一规范。`BOOL_TO_INT` 属于标准转换形式，不能说成 CODESYS 独有语法；`AND_THEN` 则是 CODESYS 文档明确标注的 IEC 扩展。

## 安装与确认加载

1. 下载本仓库，或获取[独立部署 ZIP](https://github.com/BenPeng0205/cr-st-expert/raw/refs/heads/main/downloads/cr-st-expert-4.0.0-standalone.zip)。
2. 保留完整目录，文件夹命名为 `cr-st-expert`，其中直接包含 `SKILL.md` 和配套目录。
3. 放到助手支持的技能目录。当前 Codex 官方资料列出个人技能目录 `~/.agents/skills`、项目技能目录 `.agents/skills`；其他已识别的安装位置按当前配置使用，避免安装多个同名副本。
4. 刷新技能发现或重新开启会话，明确要求助手加载 `cr-st-expert` 及其引用的规范资料。

**基础使用不需要 Python、IDE、CLI、图谱、其他技能或外部记忆服务。** 前提是 AI 助手能够发现技能并读取配套资料。

详见[部署说明](deploy/README.md)与[Codex 官方定制文档](https://learn.chatgpt.com/docs/customization/overview)。入口和详细规则目前主要为中文；英文首页不代表全部规则库已完成英文翻译。

## 写、改、审：三种提示词

**写代码：**

> 请按 cr-st-expert 编写一个功能块，实现【功能需求】。输入输出和工况是【具体条件】。缺少的信息先指出，不要自行猜测。

**改代码：**

> 请按 cr-st-expert 整理以下代码，保留现有公共接口和业务逻辑。说明修改点；涉及逻辑变化的部分先列出建议。

**审查代码：**

> 请按 cr-st-expert 审查以下代码，列出问题位置、原因和修改建议。暂不修改，无法确认的内容单独说明。

已有工程应先确认接口兼容性和原有约定。只审查一段代码，不能说整个项目已经检查通过。

## 能力边界

- 不创建或写入 IDE 工程，不编译、仿真、连接设备或下载程序。
- 不提供运动、通信等领域库的完整接口知识，需要实际库资料确认。
- 不证明库已安装、参数签名正确或控制逻辑安全。
- 不主动上传代码或记录外部记忆；助手本身的数据处理方式仍然适用。

规范审查、目标环境编译和实际功能测试分别进行，不能互相替代。

## 可选静态检查

只有选择运行脚本时才需要 Python 3.10 或更高，使用标准库即可。从技能目录执行：

```sh
python -X utf8 scripts/st_semantic_linter.py --root <ST源码目录> --strict --output <报告.json>
python -X utf8 scripts/protocol_validator.py
```

脚本只检查其实现的规则，未覆盖部分仍需审查。协议检查针对内置文本示例，不是 CODESYS 编译。

内置 `codesys_st_text_v1` 是文本交换约定，不是原生 IDE 工程或可直接导入的保证；Method、Action、Property 聚合在父 FB 文本中。已有工程可保留原生对象组织方式。

## 仓库内容

- `SKILL.md`：技能入口、流程与边界。
- `references/`、`rules/`：详细规范。
- `templates/`、`examples/`：模板和示例。
- `scripts/`：可选规划、检查和打包工具。
- `test/`、`evals/`：维护者测试和评估案例。
- `deploy/`、`docs/`：安装和公开产品契约。
- `downloads/`：独立部署包和哈希清单。
