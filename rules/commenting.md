# 注释规范

> 状态: 强制执行

## 1. 文件头

每个样本文件都应使用如下文件头：

```iecst
/// 功能    : 功能描述
/// 库依赖  : 暂无
```

`功能` 必须说明对象实际承担的工程职责，至少回答“处理什么输入/状态、产生什么输出、核心约束是什么”。禁止写“某某数据类型”“某某功能块”“某某函数”这种只复述对象种类和名称的空话。

## 2. 行内注释

- 使用 `//`
- 注释解释接口语义、单位或边界
- 重要逻辑、算法、公式、状态转换、边界保护、异常兜底、平台特殊处理必须写清楚原因、约束和风险，但每个关键块优先用 1~2 句高密度说明完成
- 平台函数、库函数或本地公共函数如果名称不能让调用者立即理解，调用行前只说明函数职责、返回单位和本段调用目的
- 复杂数学表达式前必须写出工程公式或离散化关系，说明变量对应关系、单位换算和边界保护；避免把公式推导写成教程
- 每个包含可执行代码的 `// === IMPLEMENTATION ===` 段必须包含工程师级 `//` 注释；复杂段落必须按真实逻辑块补注释，覆盖算法、边界、状态保持、单位换算或关键函数调用，禁止用固定数量指标替代可读性判断
- 简单赋值、直观布尔判断、变量名已经表达清楚的代码不要补废话注释
- 文件头注释禁止出现编程人员、时间、版本
- 无外部库时写 `暂无`；已使用外部库但名称或版本未知时标为待确认，不以 `暂无` 掩盖依赖。确认后写实际库名，例如 `Standard`；不填平台名、厂商名或“原生库”
- 变量存在物理单位时，必须先确认单位，并用 `[unit]` 标注，例如 `// 额定转速 [rpm]`
- 不写“显而易见”的废话注释

## 3. 段落注释

复杂对象建议在实现区标记之后补一段说明：

```iecst
// === IMPLEMENTATION ===

/// =======================================================================
/// 名称      : FB_MotorController
/// 功能      : 说明该对象承担什么职责
/// 库依赖    : 暂无
/// =======================================================================
/// 使用说明  : 1. 说明调用条件或文件拆分边界
///           : 2. 说明关键使用约束
/// =======================================================================
```

完整功能注释块必须写在 `// === IMPLEMENTATION ===` 之后，作为实现区最上方内容。禁止写在变量声明区。
FB / FC / PRG 的完整功能注释块必须包含 `名称`、`功能`、`库依赖`、`使用说明`。
`使用说明` 必须至少包含两条编号内容：第 1 条说明调用条件或文件拆分边界，第 2 条说明关键使用约束。禁止把这两条合并成一句泛泛描述。

工程师级段落注释的写法：

1. 先说明本段解决的工程问题，例如采样、滤波、积分、状态切换、边界钳位或输出刷新。
2. 再说明输入、输出和内部状态之间的关键关系，必要时给出公式。
3. 最后说明特殊处理原因，例如避免除零、保留余量、处理扫描周期抖动或兼容库函数单位。
4. 一段注释通常不超过 2 行；只有状态机、协议解析、复杂公式等确实需要时才扩展。

工程师级行注释的写法：

1. 只贴在关键语句前，不为每一行机械加注释。
2. 注释必须补充代码看不出的信息，包括函数语义、单位、公式、为什么这样算、失败或边界条件。
3. 对复杂表达式使用“公式 + 变量含义 + 保护原因”的短结构，单位换算只有在代码不直观时才写。
4. 数字公差、阈值和经验常量只写“用途 + 工程边界”，禁止展开成“为什么不是另一个数”的教学式比较。

当前推荐注释标准：

- 文件头：一句实际职责 + 具体库依赖，不写来源、迁移过程或对象类型复述。
- 变量声明：说明接口语义、状态含义或单位；不写“上层调用方写入”“保存中间状态”这类模板话。
- 实现区：每个关键逻辑块 1~2 句，覆盖看代码看不出的原因、约束或风险。
- 简单赋值、清晰布尔输出、显而易见的分支不加行注释。
- 数字公差示例：`// 1.0E-6 用于吸收归一化占空比的 REAL 尾差，避免近 0%/100% 输入落入普通波形分支。`
- 质量判断：以 `FB_GenSqr` 这类注释为标杆，读者应能从注释理解外部函数用途、数学关系、边界分支和状态保持方式。

## 4. 禁止项

- 禁止使用 `(* ... *)`
- 禁止乱码注释
- 禁止把多行文件头挤到一行
- 禁止实现区只有代码、只有对象头部说明或只有复述代码的空洞注释
- 禁止“本段刷新诊断、处理边界条件”“状态只在有效分支内推进”“本段执行输入边界保护和核心计算”“由本周期输入和保持量计算得到，后续输出或状态判断直接使用该中间量”“专用功能逻辑”“按该对象的输入契约刷新对应工程输出”“实现区按当前输入刷新输出”等泛化模板注释；这些句子不能证明代码逻辑已经讲清楚
- 禁止过度注释：不得用长段解释替代常量、精度背景或显而易见的赋值逻辑
- 禁止出现“为什么不是 1.0E-7”“精度边界”“百万分之一”“工程收益很小”等教学式常量比较话术
- 禁止在重写库交付源码中残留旧源库品牌字样
- 禁止写“保留原始算法语义”“字段已语义化命名”等迁移过程说明；交付注释只描述当前代码的行为和工程意图
- 禁止在 `库依赖` 中写 `CODESYS Standard 原生库`、`CodeSys Standard 原生库` 或其他“平台 + 库 + 原生库”组合
- 禁止让规则只停留在文档中；写入技能的强制规则必须同步进入测试或门禁。
