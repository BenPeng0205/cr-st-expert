# 状态机安全规则

> 适用场景：所有 `CASE eState OF` 状态机、PackML 类状态、步骤顺控、设备模式控制。

## 1. 状态必须可诊断

- 状态枚举必须带 `iInvalid := 0` 或等价非法默认态。
- `CASE` 必须有 `ELSE`，非法状态必须进入安全状态或错误状态。
- 错误状态必须保留错误码，不能静默回到 Idle。

## 2. 进入动作与持续动作分离

使用 `bFirstScan` 或等价机制隔离进入动作：

- 进入动作：初始化、锁存设定值、启动一次性命令。
- 持续动作：每周期调用 FB、检查完成条件、处理超时。
- 退出动作：清除 Execute、保存诊断、释放互锁。

## 3. Acting 状态必须有超时

凡是等待外部反馈、运动完成、通信响应、工艺完成的状态，都必须有超时保护。超时后进入错误状态，并保留错误上下文。

## 4. 命令优先级固定

安全相关命令优先级高于生产命令：

```text
Abort / Emergency > Stop > Reset > Start / Execute
```

高优先级命令必须能打断低优先级动作。

## 5. 复位不能掩盖故障

复位只允许在错误原因已解除或由上层确认后执行。复位时必须清理：

- 错误码
- 错误上下文
- 超时定时器
- 一次性命令

禁止在错误状态自动恢复到运行状态。
