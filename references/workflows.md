# CODESYS ST 规范工作流程

## 生成与修改

1. 确认对象类型、名称、功能需求和已知接口。
2. 核对库依赖资料，未知接口不编造。
3. 简短记录 generation_contract，按规则选择 DUT、GVL、FUNCTION、FUNCTION_BLOCK 或 PROGRAM。
4. 按模板编写命名、声明、注释和实现区。
5. 人工核对格式、接口、类型、生命周期和扫描周期。
6. 输出审查范围、未确认项和脚本执行状态。

既有工程保留用户对象组织，内置聚合文本仅供文件交换和示例使用。

## 审查已有代码

完整项目审查覆盖用户提供的全部 ST 文件；片段审查说明限制。按命名、注释、格式、接口、类型和扫描周期列出问题位置与修正建议。不要求图谱、编译器、CLI 或其他技能。

## 根据编译诊断修正

读取用户提供的错误及对应声明，优先修正类型和接口，然后修正引用、注释及格式。未重新执行编译时不宣称编译通过；启动编译器不属于本技能职责。

## 可选检查

用户选择且 Python 可用时运行内置静态脚本。无工具时照常完成规范审查。脚本失败如实记录，未覆盖规则仍由人工核对。
